# Step 2：并行调参执行

**目的**：执行参数搜索，收集结果，管理上下文。
**前置**：Step 1 完成（参数规划、达标标准已定义）。
**输出**：`experiment/results.json`、`experiment/progress.md`。

---

## 操作清单

- [ ] 2.1 建立实验目录结构
- [ ] 2.2 检测 GPU/内存资源上限
- [ ] 2.3 生成第一轮配置
- [ ] 2.4 并行运行（默认 5 路）
- [ ] 2.5 监控进度、收集结果
- [ ] 2.6 写入 results.json 和 progress.md
- [ ] 2.7 检查终止条件（达标则跳 Step 4，否则继续）
- [ ] 2.8 上下文压缩（每 5 轮）

---

## 2.1 环境准备

建立目录结构：`experiment/round-N/config-NNN/`

检测资源：
- GPU 型号和显存总量
- 可用内存
- 磁盘空间

---

## 2.2 并行策略

**默认 5 路并行**。

隔离方式：
- Git 项目 → worktree 隔离
- 非 Git 项目 → 复制到独立目录
- 轻量实验 → 后台进程 + 不同参数文件

**动态调整**：
- GPU 显存 > 85% → 减 1 路
- GPU 显存 < 50% → 加 1 路（上限 8）
- OOM → 该分支降低 batch_size 重试

---

## 2.3 单轮流程

```
生成 N 组配置
  → 并行运行
  → 监控进度（检查进程是否存活、GPU 利用率）
  → 中途检查（训练 20% 时，见下）
  → 收集结果（等待所有分支完成或超时）
  → 写入 results.json（格式见 `references/results_schema.md`）
  → 更新 progress.md
```

### 提前终止（Pruning）

每个分支训练到 **20%** 时做一次中途检查：
- 如果当前指标比历史最佳低 > 0.1 → **提前终止**该分支，释放资源
- 如果 loss 在前 20% 没有下降趋势 → **提前终止**
- 如果该分支 OOM 或崩溃 → 标记为 failed，不重试（本轮内）

提前终止的分支记录到 results.json（status: "pruned"），不计入正常实验统计。

目的：省下资源给更有潜力的配置，或提前启动下一轮。

### 实验对比表

每轮在 `experiment/progress.md` 中追加一个对比表：

```markdown
## Round 3 对比（最佳：config-007，dice=0.89）

| 配置 | lr | batch_size | dice | loss | 趋势 | 状态 |
|------|-----|-----------|------|------|------|------|
| config-005 | 0.0005 | 16 | 0.87 | 0.13 | → | completed |
| config-006 | 0.0003 | 16 | 0.86 | 0.14 | ↓ | completed |
| config-007 | 0.0005 | 8 | 0.89 | 0.11 | ↑ | completed |
| config-008 | 0.001 | 16 | 0.82 | 0.18 | ↓ | pruned |

参数重要性：lr=高(0.45) | batch_size=中(0.22) | weight_decay=低(0.08)
```

用户打开 progress.md 就能看到完整的调参历程和参数影响，不需要翻 results.json。

---

## 2.4 上下文管理

**上下文压缩**：每 5 轮将早期轮次的详细结果压缩为摘要（只保留关键指标和参数），释放上下文空间。

压缩策略：
- 保留：每轮的最佳配置、最佳指标、关键发现
- 压缩：失败配置的详细日志 → 只保留"为什么失败"一句话
- 删除：中间过程的调试输出

**关键信息写文件**：所有重要结论必须写入文件，不依赖对话记忆。

---

## 2.5 完成守卫

每轮结束时检查终止条件：
- 达标？→ 跳到 Step 4 生成报告
- 触发放弃条件？→ 跳到 Step 4 生成报告
- 都不满足？→ 自动继续下一轮，**不中途问用户"要不要继续"**

---

## 2.6 通知与成本

**通知**：调参完成（达标或放弃）时，通过用户的 Claude Code 通知机制告知结果，附上报告路径和关键指标摘要。

**成本记录**：记录总 token 消耗和大致费用，写入最终报告。

---

## 故障处理

通用故障规则见 `references/failure-recovery.md`。

Step 2 专属补充：

| 场景 | 处理 |
|------|------|
| GPU 被其他进程占用 | 检测并等待释放，或降低并行路数 |
| 磁盘空间不足 | 清理旧轮次中间文件，保留结果摘要 |
| 训练代码报错 | 自动修复流程（同 step1：读日志→定位→修复→验证，最多 3 次） |
