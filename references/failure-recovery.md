# 故障熔断机制

本文档定义所有故障场景的重试、降级、熔断规则。

---

## 重试规则

### 子 agent 调用失败

| 次数 | 间隔 | 动作 |
|------|------|------|
| 第 1 次 | 0s | 立即重试 |
| 第 2 次 | 5s | 等待后重试 |
| 第 3 次 | 15s | 等待后重试 |
| 3 次都失败 | — | 主 agent 降级执行 |

**降级执行**：主 agent 基于自身知识完成任务（如自行选方案而非搜索 GitHub）。降级结果仍走正常校验流程。

### 实验执行失败

| 场景 | 重试策略 |
|------|----------|
| 单个分支 OOM | 降低 batch_size 50% 重试，最多 2 次 |
| 单个分支崩溃 | 检查错误日志，修复后重试 1 次 |
| 所有分支失败 | 检查代码 bug，修 bug 后重新本轮 |

---

## 降级规则

### 并行降级

```
5 路并行（默认）
  → GPU > 85% → 减 1 路
  → 仍 OOM → 再减 1 路
  → 降到 1 路仍 OOM → 降级为 CPU 模式或减小模型
```

### 能力降级

| 能力 | 正常模式 | 降级模式 |
|------|----------|----------|
| 方案搜索 | 子 agent 搜索 GitHub | 主 agent 基于自身知识选方案 |
| 架构诊断 | 分析 loss 曲线 + 搜索文献 | 仅基于 loss 曲线判断 |
| 参数生成 | 基于趋势分析 + 贝叶斯优化 | 网格搜索或随机采样 |

---

## 熔断规则

### 质量熔断

**触发**：同一环节连续 3 次不达标。

**动作**：
1. 暂停当前流程
2. 向用户报告当前状态
3. 提供选项（见 `references/user-choices.md`）：
   - 继续（放宽标准或换策略）
   - 降低目标
   - 停止实验

### 架构熔断

**触发**：3 种以上架构各调满 10 轮，最佳指标仍距目标 > 0.05。

**动作**：
1. 停止实验
2. 生成放弃报告
3. 分析原因（目标过高 / 数据问题 / 架构能力上限）

### 总量熔断

**触发**：跨所有架构累计 50 轮仍无突破。

**动作**：同架构熔断。

## 降级记录

所有降级事件记录到 `experiment/degradation_log.md`：

```markdown
## [时间] 降级事件

- **触发场景**：子 agent 搜索 GitHub 失败（3 次重试后）
- **降级动作**：主 agent 基于自身知识选方案
- **影响**：方案可能不如搜索到的方案精准
- **后续**：继续正常流程，结果仍走校验
```

---

## 故障处理流程图

```
故障发生
  ├── 可重试？ → 重试（按重试规则）
  │     ├── 成功 → 继续
  │     └── 仍失败 → 降级
  ├── 可降级？ → 降级执行
  │     ├── 结果合格 → 继续（记录降级事件）
  │     └── 结果不合格 → 熔断
  └── 不可重试/降级 → 熔断
        ├── 向用户报告
        └── 提供选项
```
