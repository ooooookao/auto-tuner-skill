# 状态增量系统

本文档定义增量记录、快照、断点恢复的规则。

---

## 增量记录（Delta）

每步完成后写增量记录到 `experiment/delta-step{N}.md`。

### 格式

```markdown
# Step N 增量记录

**时间**：[完成时间]
**状态**：成功 / 部分成功 / 失败

## 关键产出
- [产出1描述]
- [产出2描述]

## 关键决策
- [决策1] → 原因：[...]
- [决策2] → 原因：[...]

## 遗留问题
- [问题1]（影响后续哪些步骤）
```

### 各 Step 的增量内容

| Step | 增量内容 |
|------|----------|
| 0 | 项目路径、Git 状态、外部路径、可用 skill |
| 1 | 项目目标、数据集特征、baseline 指标、调参策略、参数表、达标标准 |
| 2 | 每轮配置数量、最佳指标、资源使用、压缩事件、配置生成策略决策、采样策略变更、Optuna 使用情况 |
| 3 | 架构变更内容、前后对比、验证轮次结果 |
| 4 | 报告路径、最终指标、成本统计 |

## 全量快照（Checkpoint）

每个搜索阶段结束时写全量快照到 `experiment/checkpoint-phase{N}.md`。

### 触发时机

- 粗搜完成 → checkpoint-phase1.md
- 细搜完成 → checkpoint-phase2.md
- 微调完成 → checkpoint-phase3.md
- 架构变更前 → checkpoint-vN/（代码快照）
- 架构回溯后重新粗搜 → checkpoint-vN-phase1.md（使用架构版本号前缀，避免与之前架构的 checkpoint 混淆）

### 快照内容

```markdown
# Phase N 快照

**时间**：[快照时间]
**阶段**：[粗搜/细搜/微调]

## 当前最佳
- 指标：[最佳指标值]
- 配置：[最佳参数列表]

## 参数状态
| 参数 | 当前值 | 范围 | 是否收敛 |
|------|--------|------|----------|
| ... | ... | ... | ... |

## 历史摘要
| 轮次 | 最佳指标 | 关键发现 |
|------|----------|----------|
| ... | ... | ... |

## 下一步计划
- [计划内容]
```

## 断点恢复

### 恢复流程

1. 读最近的 checkpoint-phase{N}.md
2. 读 checkpoint 之后的所有 delta-step{N}.md
3. 合并状态，确定当前进度
4. 从断点继续执行

### 恢复检查

- [ ] checkpoint 文件是否存在且完整
- [ ] delta 文件是否连续（无缺失）
- [ ] 代码文件是否与 checkpoint 一致
- [ ] 数据集是否未变化

### 不一致处理

| 场景 | 处理 |
|------|------|
| checkpoint 缺失 | 从最近的 delta 重建 |
| delta 缺失 | 从 checkpoint 开始，缺失的步骤重做 |
| 代码被修改 | 从 checkpoint 重新复制，不保留外部修改 |
| 数据集变化 | 重新跑 baseline，更新 dataset_info.md |

## 上下文压缩与文件的关系

**原则**：对话上下文可以压缩，文件必须保留完整。

| 内容 | 对话上下文 | 文件 |
|------|-----------|------|
| 最近 3 轮详情 | 保留 | 完整保留 |
| 早期轮次详情 | 压缩为摘要 | 完整保留 |
| 关键决策 | 保留 | decision_log.md |
| 失败记录 | 可压缩 | failed_architectures.md 完整 |

压缩时只压缩对话上下文中的内容，不修改文件。
